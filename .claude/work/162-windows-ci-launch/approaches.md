# Reframe

Treat Windows validation as two independent contracts: native compilation/execution of platform code, and end-to-end launch of the artifact users install. The current idea risks turning “whole workspace tests” into a large blanket `cfg(unix)` carve-out. Keep platform-neutral tests visible; mark only tests whose `sh`/PTY semantics are inherently Unix, collect omissions from one inventory, and print names and total. A broad gate on `pty_output.rs`, `lib.rs`, or `resume.rs` would hide unrelated regressions and make the skip count look precise while silently excluding useful coverage.

Run workspace clippy and tests on `windows-2025`, then make the installer script launch the installed `Ivy.exe` under a child environment with `XDG_*` and `SHELL` removed. Give it an isolated real `%APPDATA%`, exercise the normal console startup, require a visible console window, confirm the resulting layout is beneath that profile, and require clean exit. Keep the preservation fixture separate: its current `XDG_CONFIG_HOME` setup in `packaging/windows/test-install.ps1` masks the fallback path, so reusing it as the launch proof would repeat the defect. `measure.rs` measures frame behavior; reusing its self-close path may bypass normal startup and does not prove a console opens.

The main risks are inaccurate skip accounting across mixed test modules, false confidence from testing a build-tree executable instead of the installed payload, and a smoke test that observes process exit without proving a window or APPDATA write. Existing coverage in `crates/app/src/session.rs` already tests APPDATA resolution, so the smoke test should prove that resolution is wired into packaged startup rather than duplicate that unit test.
