# Windows installed launch smoke

Use the installed `Ivy.exe` in normal mode, with a tiny disposable helper executable supplied as `ComSpec`. Its only job is to write a known marker to stdout and exit 0. Clear `SHELL` and every `XDG_*`; set `APPDATA` to a fresh runner-temp directory and `ComSpec` to the absolute helper path. Keep `PATH` free of `pwsh.exe`/`powershell.exe` so the documented shell search reaches `ComSpec`. Launch the installed binary with `Start-Process -Wait -PassThru` and a finite timeout; require exit code 0, the helper marker, and `%APPDATA%\ivy\layout.json` containing parseable JSON. The marker proves a real PTY child ran; its exit lets Ivy close naturally.

This fits existing behavior: Windows shell selection prefers a valid absolute `SHELL`, then PowerShell on `PATH`, then `ComSpec`/`SystemRoot` `cmd.exe` ([shell_integration.rs:22-37, 74-124](../../../crates/app/src/shell_integration.rs#L22)). With `SHELL` absent and PowerShell excluded, `ComSpec` selects the helper. Ivy closes the viewport after all consoles finish ([lib.rs:1324-1330](../../../crates/app/src/lib.rs#L1324)). `on_exit` captures restoration, detects the final layout and saves immediately ([lib.rs:1732-1740](../../../crates/app/src/lib.rs#L1732)); the normal startup obtains persistence from the environment ([startup.rs:21-22](../../../crates/app/src/startup.rs#L21)), and Windows path resolution falls back from XDG to APPDATA and appends `ivy/layout.json` ([session.rs:549-567](../../../crates/app/src/session.rs#L549)).

Do not set `MEASURE_*`: startup classifies any such variable as a measurement run and forbids overwriting persistence ([startup.rs:30-38](../../../crates/app/src/startup.rs#L30)). The current install script seeds XDG data and never launches Ivy ([test-install.ps1:9-15, 39-49](../../../packaging/windows/test-install.ps1#L9)).

Limitation: stdout marker plus child completion proves the console process started through Ivy's PTY, but does not prove a human-visible window was painted. If “opens a console” means a rendered frame, add a small test-only readiness signal at the first completed UI frame, consumed by the script; do not rely on `Start-Process` alone. Ensure the helper is an absolute executable with no injected `SHELL` or XDG variables in its child environment.
