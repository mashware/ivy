# Security design

Treat the current Windows user as the trust boundary; the channel is not secret from same-user processes. Create each `PanelDir` with a Windows security descriptor at creation, not `DirBuilder` defaults: owner must be the current user, and a protected DACL allows only that user and SYSTEM (full control). Validation of inherited `PANEL_DIR` verifies directory type, owner SID, protected DACL, and only expected user/SYSTEM allow ACEs; reject inherited, broad, or extra allow ACEs. Creation and validation must agree so fallback-temp directories pass.

Define `PANEL_SERVER_PID` as the third fixed `PanelDir` environment value, populated from the app PID and removed when no pane identity is passed. Windows `Producer::of_this_pane` requires it and validates the directory; after connect, compare `GetNamedPipeServerProcessId` before sending protocol bytes. Apply directory and PID checks to public `Producer::of` too, or make it test-only/internal, so it cannot bypass identity checks. PID matching prevents endpoint spoofing across app instances; DACL limits who can plant one.

Create the initial pipe with `FILE_FLAG_FIRST_PIPE_INSTANCE`, remote-client rejection, and that DACL. Keep its listening handle until a replacement instance is successfully created; use the first-instance flag only once. If replacement creation fails, retain and retry, never expose a name gap. Use overlapped accept plus a private stop event; cancel/drain I/O before closing handles, and join workers on drop. Windows tests assert actual descriptors, collision, remote, spoofed PID, and shutdown behavior.
