| Angle | Finding | Type | Severity |
|---|---|---|---|
| Fit / YAGNI | The design gives the same-UID helper/socket exchange a versioned protocol, private runtime directory, peer-credential check, authentication, and cleanup lifecycle. The directory is already private and the helper path is supplied by Ivy; peer credentials do not create a security boundary against another process running as the same user. These layers add startup and cleanup failure points to the critical launch path. Keep the gate and a bounded ready/exec result exchange, but justify each additional safeguard against a concrete failure the simpler private socket cannot prevent. | unnecessary | medium |
| Operations | Each console launch synchronously waits for scope setup, with an initial one-second target. Opening multiple consoles/restored layouts can serialize that delay on the current UI launch path. The design acknowledges this may violate responsiveness but leaves the async app-launch-flow change conditional on later measurements. A build-ready plan needs a bound on aggregate UI stall or an explicit async handoff; otherwise a slow user manager can freeze a multi-console open for N seconds while still meeting the per-operation deadline. | missing | medium |
| Attribution | The plan requires systemd `Result=oom-kill` and says to retain a unit reference until classification, but does not specify how long after direct-child exit to wait when descendants keep the scope active, or when to release the reference if the scope never becomes inactive. The generic “bounded observation window” lacks a duration/trigger. Without that lifecycle rule, ordinary long-lived descendants can keep notices pending indefinitely or the reference can be dropped before the result is available. | missing | medium |

No high-severity blocker found in the proposed pre-exec placement: the helper is the process moved into the scope and cannot run user code until release, avoiding the post-spawn fork race. The chosen D-Bus path is justified over a wrapper for preserving the PTY child identity and once-only fallback behavior.
