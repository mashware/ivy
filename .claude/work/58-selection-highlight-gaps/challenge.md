# Challenge — design #58

| Angle | Finding | Type | Severity |
|---|---|---|---|
| 2a/2b Fragile assumption | **Translation keeps each glyph's subpixel phase, and that phase belongs to the old pen.** epaint 0.36.1 turns subpixel binning on by default (`TextOptions::subpixel_binning: true`, `text/mod.rs:62`). The run's pen goes `k × advance`. `allocate_glyph` (`font.rs:622`) puts the integer part in `glyph.pos.x` and **rasterises the fraction into the texels** (bins 0, ¼, ½ and ¾ px). At ppp 1 with advance 7.84, glyphs 1–3 get bins ¾, ¾ and ½. The integer part (`p`) moves onto the cell exactly as the design says, so quads land on whole pixels. The ink inside them, though, sits up to 0.75 px off the grid. The per-cell path always rasterises at bin 0. So spacing still varies by up to ¾ px inside a run, and it jumps where a selection edge re-cuts the run, because the new run's pen restarts at 0. That is the reported symptom, only smaller. | missing | high |
| 2 Guard model | AC3/AC4 compare **quad positions and sizes**. Those match even with the bin defect above, so the tests would pass while the defect stays. This is the case the design's own card warns about (`a-guard-written-from-the-same-wrong-model…`). AC3 should assert identical `uv` (the same atlas texels) for unsubstituted glyphs against the per-cell path. AC4 should assert unchanged `uv`/ink for glyphs outside the edge. | missing | high |
| 3 Simplification | One way to remove the bin problem: set `FontTweak::subpixel_binning = Some(false)` on the face the ligature family registers. Glyphs then rasterise at bin 0 with `h_pos.round()`, and an unsubstituted glyph reuses the same cache entry as the per-cell path. Per-cell galleys already start at a whole pixel, so they are unaffected. Without it, "drawn exactly like the per-cell path" (summary) is false. | missing | medium |
| 2a Cell mapping | `round(p / advance)` holds. `p` is off the pen by under 1 px and the advance is about 8 px. Shaping keeps `glyphs.len() == char_count` through zero-width continuation glyphs (`text_layout.rs:226–229`), which `tessellate_glyphs` skips because `uv` is nothing. Uniform advances are already forced by `layout`'s per-char `glyph_width` check and its row-width check. The glyph's index would also work for an ASCII run; either is fine. | — | low |
| 2 Edge | A true multi-cell ligature glyph keeps its design width `n × advance` but sits over `n × cell_width`. For Ubuntu Sans Mono 14 at ppp 1 that is about 0.84 px of overhang per cell into the next cell. The same holds for JetBrains-style `calt` connectors, which are drawn for `advance` spacing and now overlap by `advance − cell`. Probably invisible, since the overhang is same-colour ink and nothing is cut, but neither the Edge clause nor the manual check AC6 names it. | missing | low |
| 2c Root cause | Plausible. The reporter's config has `font.ligatures = on`. Squeezed runs are resampled from a linear-filtered atlas. Runs are split by `same_style`, and that includes `selected`, which explains why it is tied to selection and comes and goes. Background rects are not touched by `on_grid`, so "fragmented highlight" really means smeared glyphs on a light background; the design says so. The rect-seam emulation fairly rules out the alternative. | — | — |
| 4 Frame cost | No undeclared work. Translation replaces the per-vertex multiply, so it is still O(vertices). It runs inside the existing `LigatureCost.spent` span, already declared as a subset of painting. The clone happens today too. | — | — |
| 1 Need | Nothing unnecessary. Keeping `layout`'s width refusal costs nothing and is what makes the cell mapping valid. Recomputing `rect`/`mesh_bounds` keeps culling honest. The amendment to `02-decisions.md` is a project rule. | — | — |
| 5 Idiom | The three ADR rows are fair, and the third (per-cell repaint loses glyph ids) is correct. One alternative is missing: **lay the run out at `size × cell/advance`**, which gives native rasters on the grid with no resampling. It loses because glyphs come out smaller than in per-cell cells, and a selection re-cut would then change glyph size. Listing it would close the set. A **binning** row (above) is the decision the table actually lacks. | idiom | low |

**Verdict:** the direction is right, but the plan does not reach its stated invariant until subpixel phase is handled and the tests assert texels, not quad geometry.
