# Design challenge #56

Paths relative to the worktree.

| Angle | Finding | Type | Severity |
|-------|---------|------|----------|
| 1 Fit | **Pane-child cell + "start time recorded at `term-core/src/lib.rs:450`" duplicates what exists.** `lib.rs:450` *is* `foreground_scope()`, and `ForegroundScope` already holds the child's pid, birth, a pidfd and the pty's stop flag (`foreground/linux.rs:11-43`). `resume.rs:7-31,148` already routes one through a swappable cell to the connection thread. The label needs its own scope instance (today one is built only while session capture is on, `resume.rs:132-150`), but no new type and no new recording. | unnecessary | medium |
| 1 Fit | **The read_if_newer gate is not a new mechanism.** `refresh_file` already reads through `read_if_newer(dir, last_good.written_at)` (`panel.rs:390-392`). `deliver`/`patch` stamp `written_at = now` (`driving.rs:353`, patch commit). So AC9 follows on its own once `Done` gets past the holder early-return (`panel.rs:377-381`). Keep AC9 as a regression test. Drop it from the defences table as a cost. | unnecessary | low |
| 1 Fit | `published_by`, `Holder.done` and the patch-ownership rule all hold up. `release` drops the holder but keeps the document (`driving.rs:466-478`), so the label cannot live on `Holder`. `patch` checks only the holder (`driving.rs:397-401`), so after `done` it would patch a newer file's document. | — | no finding |
| 2 Fragile | **"The child is unreaped while `Pty` owns it" is false.** `Pty::exit_success` reaps with `try_wait` (`lib.rs:455-462`), and `lib.rs:1025` warns about exactly this. The birth check (plus the pidfd on Linux) still covers pid reuse, so the mechanism holds. But the premise must not go into a comment or a rationale: it is a claim about current behaviour, and it is wrong. | idiom | medium |
| 2 Fragile | **The stat can race the bind.** `control.sock` is bound at `opening.rs:646` (`listener.rs:208`), *after* the program is spawned at `opening.rs:621`. An agent launched as the pane's program (`resume.rs:114`, `launch_exact`) whose bridge answers `initialize` first loses the instructions for its whole session. The window is sub-millisecond against an agent's startup time, so it is unlikely, but the design never states the ordering. | missing | low |
| 4 Production | **macOS needs more than `descends` and `peer/macos.rs`.** `ForegroundScope`'s only field is `cfg(linux)` (`foreground.rs:11-15`). `Peer::is_alive` returns `false` off Linux (`peer.rs:47-50`). Any reuse of `is_alive` or the scope on macOS turns every verdict into "cannot tell", so the label never shows there and nothing fails. The split must also keep a fallback for every other target, or Windows stops building. | missing | medium |
| 4 Production | Frame cost: the verdict runs on the connection thread. In `Done`, the file read happens inside the already-declared file stretch (`PanelRefresh`). The label is one more input to `warning()`. Nothing new to declare. | — | no finding |
| 5 Idiom | **`endpoint::reachable` is named for what it does not test.** A stat says the path exists. After an Ivy crash the socket file stays and connects fail. `exists`/`present` would be honest. The stat itself is still right (D88 discarded the connect). | idiom | low |
| 5 Idiom | **`Done(C)` refusing D carries a rationale the design itself undoes.** "A borrowed identity takes a living holder's pane" cannot be the reason: after `done` the file is read, so any same-uid process takes the pane by writing `panel.json`. The checkable reason is AC7: agents publish `done` at every stop and keep working (the bridge's own instructions say "republish without it as soon as it stops being true"), so C must be able to re-claim. | idiom | low |
| 3 Simplification | Beyond the scope reuse above, none. `descends` as a sibling of `inspect_descendant` reuses the walk. Splitting "outside" from "cannot tell" comes down to only the `parent == 0` branch (`foreground/linux.rs:123-125`). | — | no finding |

Overall: the design is tight on product mechanics. The two medium findings are about reusing `ForegroundScope` and about the macOS port's silent "cannot tell".
