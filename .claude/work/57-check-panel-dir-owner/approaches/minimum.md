# Minimum approach

Add `endpoint::private_to_this_user(dir)` as the single Unix check: use `symlink_metadata`/`lstat`, require a real directory owned by the effective uid, and reject any group/other permission bits. Return an `io::Error` that names the path and distinguishes a missing directory from an insecure one. Keep it a no-op on Windows while channels are unsupported there. Call it only at inherited-identity doors: in `Producer::of_this_pane` after validating the whole identity and before `Self::of`, and in `session::helper::exchange` before its direct `ConnectOptions` call. Leave generic `Producer::of` and `endpoint::connect` alone so app-owned paths and existing internal callers retain their contract. In `ivy-session`, preserve `exchange`'s error text in the returned helper error instead of replacing it with “cannot reach”.

In `ivy-opencode.tsx`, add a small `lstatSync` check for `PANEL_DIR` at the start of each `connect()` attempt, checking directory type, `uid === process.geteuid()`, and `(mode & 0o077) === 0`; on failure, do not call `createConnection`, and schedule `connect` again after one second. This keeps the check fresh across retries.

The main risk is check-then-connect: the directory could be replaced after validation, though the 0700 owner check closes the planted-directory case described by the ticket. JS and Rust must agree on symlink, missing-path, uid, and mode behavior. A bad idea is putting the guard in `endpoint::connect`: it would silently widen scope to explicit/internal callers and could break legitimate application connections that do not use inherited identity.
