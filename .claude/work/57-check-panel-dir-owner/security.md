# Security review: #57

The threat is credible: an inherited `PANEL_DIR` survives console cleanup, while `PANEL_ID` is guessable; a foreign user can plant `control.sock` in the recreated pathname and receive panel documents. The two Rust inherited doors currently connect without checking the directory: `Producer::of_this_pane` reaches `Self::of` at [client.rs:99-115](../../../crates/panel-control/src/client.rs), and `exchange` connects directly at [session/helper.rs:83-91](../../../crates/panel-control/src/session/helper.rs). The OpenCode plugin likewise calls `createConnection` at [ivy-opencode.tsx:27-30](../../../resources/agent-integrations/opencode/ivy-opencode.tsx).

Use one Unix `private_to_this_user` guard in `endpoint.rs`: `symlink_metadata` (lstat semantics), require a real directory, effective-uid ownership, and `(mode & 0o077) == 0`. Run it at both inherited identity doors before any connect; preserve its path-bearing error through `ivy-session`. For testability without root, factor the metadata predicate to accept an expected uid and test foreign ownership with an injected uid. Missing metadata must have a distinct “gone” error; symlinks and insecure ownership/mode must refuse. Keep the generic explicit `Producer::of`/`endpoint::connect` contract untouched.

In OpenCode, synchronously lstat `PANEL_DIR` at the start of every `connect()` attempt, before `createConnection`; on failure, log/refuse and schedule another attempt in one second. The existing reconnect timer is at [ivy-opencode.tsx:68-75](../../../resources/agent-integrations/opencode/ivy-opencode.tsx). Add coverage proving a failed check creates no socket and each retry rechecks. The current mock test hardcodes the test process environment and mock connections ([plugin.test.mjs:15-29](../../../resources/agent-integrations/opencode/plugin.test.mjs)); inject uid/stat behavior or use real temp dirs without root.

Check-then-connect leaves a narrow replacement race, accepted for this ticket. Peer-uid verification, arbitrary script file transport, and changing `whole_identity` remain out of scope. `endpoint.rs:3-7` currently claims a client-side check is useless; update that rationale with the new inherited-identity boundary.
