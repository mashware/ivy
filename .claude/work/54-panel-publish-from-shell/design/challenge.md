# Design challenge #54

Paths are relative to the worktree.

| Angle | Finding | Type | Severity |
|---|---|---|---|
| 1 Need | **The Codex argument check and `KERN_PROCARGS2` are recovery policy, not identity.** Reusing `verify::root` "unchanged" brings in `check_mode`. That check accepts only resumable argument shapes (`ai_sessions/verify.rs:55,104,114-140`). On Linux today, `codex --model x` or `codex "prompt"` would get no holder root, so every hook would be refused with AC3's "not an attested client". The check is also the only reason for `KERN_PROCARGS2`. Without argv, npm-wrapped Codex still passes, because the native child is selected (`verify.rs:21-33`, `macos-attestation.md` §5). Drop `check_mode` for publishing, and the macOS argv copy goes with it. | unnecessary | high |
| 2 Fragile | **macOS discovery finds no client.** `is_native` accepts only ELF (`ai_sessions/programs.rs:215-219`), and `codex_binary` knows only Linux targets (`:247-250`). On macOS, `discover()` returns nothing and every attestation is denied. `programs.rs` is missing from the module list, so AC9 cannot pass. | missing | high |
| 2 Fragile | **The listener's holder record is lost on a minimised window.** The record is set only when the window answers `Taken`. If the holder's `panel_set` times out (`listener.rs:802,832`), the window still applies it later, but the record is never written. Hooks are then refused with "nobody holds" in exactly the scenario AC6 exists for. | missing | high |
| 3 Simplify | **There are two copies of the hold.** The listener records `(Connection, Option<ClientRoot>)`, and the window gets `Holder.root` plus a `root` field on `What::Publish` (design lines 99, 104, 114). The apply-time re-check could compare the **connection** the listener saw, which is D43's own identity (`driving.rs:208-223`). Then the window never needs roots. | unnecessary | medium |
| 5 Idiom | **ADR row 1 rejects "any attested client" for a reason that cannot happen.** A worker inside the console is already denied, because `root` refuses a second recognised client in the chain (`verify.rs:37-46`). The worker's own bridge is also a different connection (D88, `02-decisions.md:9358-9361`). The real reason is AC3, a pane held by a script. | idiom | medium |
| 2 Fragile | **A holder patch after an overlay fails on its own keys.** Ops target the hook's lines, and a key the agent set that flow's render lacks is refused: `no line of this panel carries the key` (`panel-contract/src/patch.rs:455-457`). D88 tells agents to patch by key. AC5's "applies over what is on screen" hides this. | missing | medium |
| 2 Fragile | **Composition can produce a panel neither producer published.** The holder's buttons survive with the hook's lines, so a button can outlive the question it answered. A hook's new `wait` line can also sit beside old buttons. D42's "settled" check covers layout, not meaning (`02-decisions.md:6396-6403`). The literal command is still painted, which keeps this at medium. | missing | medium |
| 4 Ops | **"Nobody holds" is the normal state, but the command reports it as a failure.** Before the agent's first `panel_set`, and after it quits, every tool call's hook exits 1. Whether flow or Claude shows that as hook-error noise is unverified. The ticket wants one FLOW line to behave quietly. | missing | medium |
| 4 Ops | **Widening the `ai_sessions` gates turns on session recovery and its relaunch on macOS** (`ai_sessions/mod.rs:3-34`, AC10). The ticket did not ask for that. Only `verify` and `programs` are needed. | unnecessary | medium |
| 2 Fragile | **Programs are discovered once per pane and compared by exact executable path** (`verify.rs:23,102`). A client that updates itself to a new versioned path is not recognised in that pane any more. A Claude installed through npm (`cli.js`) is never attested (`programs.rs:43-44`), and the refusal blames the holder. To be checked. | missing | low |
| 3 Simplify | **Peer capture only happens when a session handler exists** (`listener.rs:390-393`). The plan does not mention moving that gate to `attest`. | missing | low |
| 5 Idiom | **`architecture.md` contradicts the chosen design on two points.** §2/§4 still has the answer wait for the window (5 s) and say "compact output is never wider". The second is false: `1e5` becomes `100000.0`. The design's encoded-bytes check covers the bound, but the evidence document is stale. | idiom | low |

No findings on the macOS `pidversion` or before-and-after snapshot checks: PID reuse is real, and Linux already has the twin at `foreground/linux.rs:89`. The apply-time re-check is needed under any queue-then-answer shape. The `· hook` row is cheap, and it is needed because `header` is kept.
