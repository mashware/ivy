# Challenge — trust boundary / abuse (#54)

| Angle | Finding | Type | Severity |
|---|---|---|---|
| Abuse: who passes | The proof attests **every live descendant** of the client root, not "its hooks". The publisher walk skips group, session and tty checks (`term-core/src/foreground/linux.rs:76,83-87`, through `verify.rs:19`). So every third-party MCP server Claude spawns can now set `lines` and `attention` on a held pane, and so can every tool child whose parent stays alive. Before this change, all of them were refused by D43 (`02-decisions.md:6507-6511`). F2 (`03-design.md:136`) says "hooks are as trusted as the agent", but the set is wider than hooks. D80's `max(panel, signal)` (`architecture.md:46`) keeps a native wait visible, but not a panel wait. | missing | medium |
| Abuse: AC3 premise | AC3 says a script holder is refused (`03-design.md:80`). But a script the agent started also descends from the agent's root, so its hold resolves to that same root. Hooks then overlay another producer's panel. The root binding merges every producer under one agent into "the holder", which is the collision D43 exists to stop (`02-decisions.md:6503-6505`). | missing | medium |
| Abuse: escape | `setsid` keeps the parent pid and passes. A double fork or reparenting to init or a subreaper breaks the chain and is **denied** (`linux.rs:125-127`). A nested client is denied (`verify.rs:37-46`). Escaping only narrows the set. Not a finding. | — | — |
| Buttons | Buttons are laid out above the body (`app/src/panel.rs:907-948`), so hook lines cannot push them off. A press resolves to `last_good.actions` (`panel.rs:449`). Commands cannot be relabeled. **But AC1 is the orphan case by design.** The holder's `wait` question is replaced, its `Decision` line disappears, and the buttons that answer it stay pressable (`03-design.md:78`). A reply like `1` or `y` then goes to whatever the program asks next. D42 only accepts a label that misdescribes a command when one author wrote both (`02-decisions.md:6478-6480`). | missing | medium |
| Consistency: order | The holder's `panel_set` and the hook arrive on two connections. Precedence is "the last to arrive wins" (`architecture.md:50-56`). A hook rendered from files before the agent's `panel_set`, or a `PostToolUse` that fires after that very MCP call, clears a fresh `wait`. That is the operating system's scheduling, which D43 discards (`02-decisions.md:6509-6511`). "Holder wins whole" holds only for later `panel_set`s. | missing | medium |
| Consistency: aftermath | When the hold ends, `painted` is forgotten (`03-design.md:184`). The hook's lines then stay under the holder's bare source, without `· hook`, until the file publishes again. That is misattribution. A publication for holder A is never applied over a different root: it is re-checked at apply time (`03-design.md:187`). Same root means same agent, so applying there is accepted. | missing | low |
| macOS: environment copy | `KERN_PROCARGS2` copies Codex's environment, which holds API keys and tokens, into Ivy on **every** `current()` call, so on every publish (`verify.rs:104`). The bytes are freed, not zeroed. The evidence says "this is an owner decision" (`macos-attestation.md:40-41`), but it was "taken in auto" (`03-design.md:49`). | missing | medium |
| macOS: token and lifetime | `LOCAL_PEERTOKEN` is captured at connect time, like `SO_PEERCRED`. Passing the descriptor to another process needs a cooperating descendant that is already attested. kqueues are not inherited. `pidversion`, then `p_uniqueid`, then the two-snapshot pattern match Linux. Two claims are reasoned only: that the uniqueid is stable across `exec`, and that `TIOCGPGRP` works on the master. Both fail closed, and AC9 gates them. Not a finding. | — | — |
| Hard rules | A foreign `panel.json` gets no new route, because the hook's `actions` are dropped (`03-design.md:177`). `PANEL_ID` is never a credential, as AC2 shows. The endpoint scopes the pane. No hard rule is broken. The only stretch is "actions visible before they run": the command is visible, and its meaning is not (the Buttons row). | — | low |
